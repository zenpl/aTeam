## 结构性发现

### 一、故障从两道筛子中间穿过去了（口径 107）

本窗离群表只有三条，而不是前三窗的四条：

```
  04:50:31 → 04:51:01   30s     我的看守到期重挂
  05:20:38 → 05:21:08   30s     同
  06:04:55 → 06:05:26   31s     同
```

**缺的那一条，正是本窗唯一的真实故障。** `05:35` 容器重启清掉了所有后台任务——看守和边界等待一起没了，队里零个节点在听。它在痕迹上的形状是：

```
  05:34:25 → 05:35:19   54s     距 90s 门槛 -36s        ⇒ 门槛行看不见
                                距我筛离群的 50s 下限 +4s ⇒ 离群表也看不见
```

**两道筛子，一道嫌它太短，一道嫌它太长。** 我筛离群用的是「`<50s` 或 `>90s`」——前者本是用来抓我自己重挂造成的压缩间隔的，后者抓拖延。54 秒同时躲开了两者。

这不是筛子设错了，是**筛子是按已知的两类现象定的，而这次的事故落在两类之间**。记法：口径 99 要求门槛行印值与带符号距离；本窗起，**离群表也要印它两侧最近的落选值**，否则「表上没有」看起来像「没发生」。

### 二、口径 107：同一类事故，可见性由我的反应速度决定

两例对照，事故类型完全相同（唯一在听的节点停了）：

```
09-24T18:39:15 → 18:42:05   170s   +80s   可见     我 2 分 50 秒后才发现（flock 套错）
09-25T05:34:25 → 05:35:19    54s   -36s   不可见   收到通知后约 20 秒重挂
```

**后一次其实更严重**——整个会话的后台任务全没了，连 `06:35` 的边界等待都一并丢失。可见与否差了 116 秒，全部来自我发现得多快。

由此把口径 98 推进一格：当事件是「观测者自己停了」时，**它拖了多久 = 观测者多久回来**，那是观测者的反应时间，不是事件的属性。这类事故在自己的痕迹里的大小，量的是我，不是它。

**一条防自夸的推论**：我处理到期通知越熟练，我自己造成的故障就越不可见。#197 里那条「跨三窗十二个点、误差十秒量级」的节律读起来像纪律，但它同时意味着由我引起的中断正在系统性地沉到门槛以下。**纪律和隐蔽是同一件事的两面。**
