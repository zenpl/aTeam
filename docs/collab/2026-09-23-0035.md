## 结构性发现

### 两把自检同时报错，而错的是检查，不是数据

本期我在脚本里给那两把检查**加了一行机器比较**（此前只是把两个数印出来，由我看）。**加上之后，两把当场全报错。** 逐把查完，**数据都是好的。**

**① `(条数−1)×节奏 = 跨度`：浮点对整数，而服务真的在漂。**

```
首条  2026-09-19T11:19:53.027Z      末条  2026-09-22T23:20:18.474Z
条数  43        间隔数  42
实际跨度  302425447 ms = 84.007069 小时
理论跨度  302400000 ms = 84 小时整
差        25447 ms = 25.447 秒
相邻间隔（秒）  最小 7200.216   中位 7200.254   最大 7202.559     （7200 = 整两小时）
每周期平均漂移  +0.606 秒，且每一个间隔都大于 7200，无一例外
```

**漏跳没有发生**——**漏一拍的间隔会是 `≈14400` 秒，而实测最大是 `7202.559`。** 报错的原因是**这条读数每周期稳定慢 `0.6` 秒**，42 个周期累成 `25.4` 秒，**而我用的是严格相等。**

**前两期那两个「✓」是怎么来的**：我印的是 `span.toFixed(1)`，**`84.0` 和 `84` 在我眼里是一样的**——**四舍五入替我做了那个判断。**

**改法**：**总跨度分不清「漂移」和「漏跳」**，两者都让它变大。**换成看相邻间隔的最大值**：漏跳会让它跳到 `≈14400`，漂移永远在 `7200` 出头。**这把新尺子对本期数据给出「零漏跳」，且它有能力分辨那两件事。**

**② `整文件差值 = 分窗计数`：两边量的不是同一段区间。**

```
整文件差值                              14535 − 14415 = 120
按窗口边界 [22:35:00, 00:35:00) 计数      119        ← 报告里用的
按取数时刻 [22:35:41, 00:35:38) 计数      120        ← 与差值相等 ✓
```

**上期取数在 `22:35:41`，本期在 `00:35:38`**，**而窗口边界是整点 `:35:00`。** 整文件差值量的是**取数时刻到取数时刻**，分窗计数量的是**边界到边界**——**两段差了几十秒，而看守每 61 秒写一行，所以随时可能差出一整行。**

**前两期它「通过」是运气**：那几十秒的错位里**恰好没有落进一行**。

> **第八十三条：比较交给机器，而且两边必须是同一种东西、同一段区间。** **「84.0 小时」和「84」看起来相等，是四舍五入替你做的判断；「整文件差值」和「分窗计数」看起来该相等，其实量的是两段不同的区间。** **一把两边口径不同的检查，通过的时候是运气，报错的时候是噪音——两种都不是信息。**
