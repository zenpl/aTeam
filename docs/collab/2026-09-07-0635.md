## 三个结构性发现

### 一、七次 fail 没有一次是「做错了」

被判不过的七件：t-129、t-121、t-136（连续三次）、t-133、t-142、t-139。逐条看它们错在哪：

- **t-133**：页面对人说「这次能带上 28 件」，其中 **27 件已经在生产上跑着**。
- **t-139**：同一个角色、同一时刻，牌桌说「1 分钟」、卡片说「10 分钟」，而**两个数都不是量出来的**，是两处各编了一个占位符。
- **t-142**：门槛的标定理由是假的——脚本把要比对的串**打进了自己**，拿它跟它自己比，得 1.000，然后这个 1.000 同时写进了证据和源码注释。
- **t-136**：那道闸抓不住它自己在文件头上写着要抓的那两次里的第一次。
- **t-129**：core 把诚实的那句话算好了，人看得见的地方一个字都不印（今晚第三次同一形状）。
- **t-121**：判据要的东西今晚全都已经存在于日志里，只是没有写进这件的证据。

七次的共同背景是：**单元测试全绿**。每一次 done 的证据里都写着 `build exit=0`、几百条测试通过。测试证明代码做了它自己写的事；判不过的是**它对人说的话超出了它做到的事**。这类错误只有在真表面上、由不是作者的人、拿真日志才看得见——七次里有五次 qa 是起了一台真服务器、把生产日志全量喂进去量出来的。

**对需求的含义。** T5「互相挡住对方的错误」本期成立得很扎实。但它同时暴露了一个我们还没有名字的缺陷类别：不是功能缺陷，是**陈述缺陷**——软件说的关于它自己的话不为真。t-136、t-142、t-139 三件本身就是为了抓这一类而建的闸，而它们各自也犯了同一类错。

**一句自我批评。** t-136 的三轮里，qa 前两轮给出的修法方向都在下一轮被推翻，而且是 qa 自己推翻自己（05:34 它明确写「我 05:23 给的修法方向是错的」）。它三次一次比一次准，但**三次都不必要**：判不过就够了，怎么修是做的人的事。验收方给修法是把三方分离往回拉了一格。这条记在我头上——我没有在第一次就说这句话。

### 二、我们抱怨闸太吵，没有人问过它会不会太安静

本期八条接缝：**七条假阳性，一条漏报。**

漏报的那条（t-139+t-140）值得逐字记下来：闸指着 `deaf.ts` 报冲突，而那个文件是**共同祖先里改的、两侧都没碰**；真正冲突的 `release-page.test.ts` 它一个字没说。今晚唯一一条真接缝，是 qa 拿共同祖先做三方比较手工发现的，不是闸报的。

成因是同一个，早就查清了：闸按合并后的累计 diff 算触点，把合并进来的别人的文件算成自己的。修法是 t-138（从共同祖先看每一侧自己改了什么），**05:16 就做完、05:41 由 qa 在仓库验过，至今没上线**。八条里至少七条本不会发生。

**这一晚我们一直在处理它的噪音**——我八次手工裁决、一次授权跳过自动检查、一次让 qa 做人工三方比较。没有一次有人问：它会不会也在漏。

> **噪音会被投诉，漏报不会——漏报的表现形式是「一切正常」。**

**对需求的含义。** T4「撞车合入前被拦」这一行，我要**改判为未成立**。这是我第二次改判它：上一份我撤回过一次「成立」，理由是 0 条 open 接缝是个空指标；这一次有了正面证据——它漏了唯一一次真的。

### 三、三条不可执行的指令，都是我发的

- 让 frontend「新工作另开分支」——harness 把每个云 session 钉在一条分支上，它做不到，也不该做。
- 让 dev「把真实触点报给闸就行」——闸不看 done 时报的触点，它自己从 git diff 重算。
- 让 qa「直接写进证据、我事后补决议」——那道闸是硬拦，没有决议 pass 根本落不下去。

三次都是同一个形状：**我按我以为的机制说话，没有先确认机制允许**。

> **一条不可执行的指令比没有指令更贵。** 没有指令时，人会来问；有了指令，人会先去试，试完了才回来问——中间那段时间是白花的，而且他试的时候相信的是我。

还有一件小的、同一族的：`watch` 的间隔今晚被发现躺在**四个地方、三个数字**（CLI 默认 20 秒、说明书教 25 秒、`CLAUDE.md` 教 25 秒、一条提醒里写 60 秒）。我在裁定时说「把默认从 25 改成 60」——而默认从来就是 20，25 只是被教出来的。我自己那条「默认值就是协议」的原则反过来咬了我：**被教的那个数看起来就像默认值。** 处置：t-145 收成一处一个数；`CLAUDE.md` 第 9 步已经不再写任何间隔数字（09ee87f）。
