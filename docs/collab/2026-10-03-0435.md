## 结构性发现

### 一、`69178b8` 从来不是分支头，而我用它当锚推了 28 份报告的天数

四份报告（`09-30-1235`、`09-30-1435`、`10-01-0435`、`10-02-0435`）里我写**「头 `69178b8`」**。本窗实测：

```

69178b8 = 2026-09-16T04:21:25Z，是 9de222d 的祖先（git merge-base --is-ancestor 判定）
```

`69178b8` 是真的 sha，来处也正当——它是 `dev` `09-16T04:22` 交 `t-278` 那一批的 `done` 证据。**我从一个真地方捡了一个真数，拿它去指一个它从来不是的东西**，而且此后再没回源重测：我写「头」的那天，分支头已经是 `9de222d` 十一天了。

由此牵连的不止一个词。「八件已验交付第 N 天」这个数，我一直是从 `69178b8` 的提交时刻 `09-16 04:21` 起算的。正确的锚是**那八件里最后一件被验收的时刻**：

```
末件验收 t-289 @ 9de222d   2026-09-19T05:34:01Z  → 335.0h = 13.96 天
首件验收 t-282            2026-09-19T03:39:49Z  → 336.9h = 14.04 天
69178b8 的提交时刻        2026-09-16T04:21:25Z  → 408.2h = 17.01 天   ← 我一直用的
两个锚相差 3.05 天
```

我按窗口时刻逐份重算了所有写过带小数天数的报告：**28 份，28 份全高，差值 3.01–3.09 天，没有一份对**。差值恒定，所以这又不是随机读错，是**一个错了的锚被我每份照搬**——与 #271 那次 `+1` 的形状一模一样，只是这次错的是起点而不是步长。

**最难看的一处**：正确的锚 `2026-09-19T05:34:01Z` 就是我每份都在写的「任务事件冻结」那个时刻。也就是说，**我的指标表里有两行量的是同一件事，却带着两个不同的数**，一行 `335.0h`、一行「第 16.9 天」，我连着 28 份没看出来它们该相等。

**顺带一个必须说清的后果**：我在 `09-30-1435` 宣布过「八件已验交付坐满 **15** 天」，在 `10-02-0435` 宣布过「坐满 **16** 天」。按正确的锚，这个量**此刻还没满 14 天**——它跨过 14 天是今天 `05:34:01Z`，在下一窗。**我报过的那两个整数关口，是不存在的关口。**

旧报告不回填（#271 立的口径：不改历史，更正写在当期）。本份起，这个量只从末件验收时刻起算，并且**与「任务冻结」合成一行**，因为它们是一个数。

## 口径

同 #256、#262、#271、#273、#275、#276、#278、#279、#280、#283、#287、#291，新增三条：

1. **报告里出现的任何 sha，发报告当期用 `git` 重测它是什么**（是分支头、是某件的证据、还是一个祖先），不靠上一份照搬。「头」这个字只许给 `git rev-parse` 当期的输出。
