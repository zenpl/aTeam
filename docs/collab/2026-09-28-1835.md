### 二、口径 158：一把对着不存在的文件跑了 140 次的尺子（本份的自我更正）

每次重挂后我都跑这半边检查，来自口径 100（`2026-09-24` 立）：

```
head -2 out.txt 2>/dev/null | grep -q WATCH-ERR && echo "有 WATCH-ERR" || echo "无 WATCH-ERR"
```

**`/tmp/pm-cli/out.txt` 从来没有被任何脚本写过。** Monitor 的真输出在 `tasks/<任务 id>.output`。`2>/dev/null` 吞掉 `cannot open`，`head` 无输出 ⇒ `grep` 退 1 ⇒ **永远打「无 WATCH-ERR」**。会话记录里这个写法出现 **140 次，全部空转**；今天我偶然漏写 `2>/dev/null`，它才现形。

**这正是 `newtells.sh` 注释里「洞二」的第三次发生**——两个不同的东西长得一模一样。前两次是「抓取失败」与「没有新东西」、「四天前」与「此刻」；这次是「文件里没有 `WATCH-ERR`」与「文件不存在」。**而这一次是我在检查那个洞的工具里，用同一个 `2>/dev/null` 又造了一遍。**

后果逐条核过，不是推断：

```
① 拉取失败的账历来由 watcherr.log 独立记（现 29 条）⇒ 报告里「拉取失败 0 次」不受影响
② 自退实例历来 3 次（09-18 11:59、09-21 11:35、09-24 18:41），逐个核当期报告，三次全被记下
   真正起作用的是「重挂前锁空闲 + 重挂后锁被占」这一对，不是这半边
③ 被推翻的是一句已发的话：2026-09-24-2035「本窗其后三次重挂都跑了这一步，都通过」
   ——那一步没有跑，它的「通过」是空的。这是本份的自我更正。
```

**改法不止是改路径。** 健康看守的 output 要到期或收尾才落盘（实测 4 例：重挂后 `30m07s / 18m34s / 30m05s / 30m05s`），自退实例在**同秒级**落盘（实测 3 例）。两类相差三个数量级、无重叠，所以：

- 口径 100 那句「重挂后读 output 首行」在健康情况下**根本无从读起，从来不可能『通过』**；
- 正确的判据是**文件在不在**，首行只在「已出现」这一支里用来分辨原因。

新脚本 `verify_rearm.sh` 做了**双向标定**才换上（喂在跑的报「还在流」，喂已知自退的 `bx6d3325m` 报「已落盘 96 字节，首行 WATCH-ERR」）。**只换不标定，就是再造一把未核过的尺子。**
