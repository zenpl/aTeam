## 三个结构性发现

### 一、T4 是空的，而我用一个空指标证明了它三次

**事实。** pd 00:08 指出：touches 是 claim 时猜的，dev 这次四个文件全猜错；接缝完全建立在 touches 上，猜错等于那条接缝根本没声明，两个人真碰同一处系统不会响。

**我的错。** 三份报告里我都用「期末 open 接缝 0 条」证明 T4 成立。**0 可能是真没冲突，也可能是没人声明对地方**，我从没把这两种分开过——而且我选了让自己满意的那个解释。

**已做。** t-105（done，dfc9d2b）：done 时 touches 是最终值、按它重算接缝、冒出新接缝挡住 done；平台层不认识 git，项目层从 diff 算，没有 diff 的介质退回手工——这一层是 pd 拦下我的越界后定的。今天 dev 四个文件全猜错的场景做成了回归测试。

**对需求的含义。** T4 本期**从「未成立」变为「成立」**，同时此前三份报告说它成立是错的。

### 二、一种错误伪装成另一种，今天出现了四次

- 服务端有能力但你的 CLI 太旧 → 看起来像「没这个能力」（t-080，今天的 P0）
- 外呼地址配了但不会响（邮箱当 webhook）→ 看起来像「配好了」（t-084）
- 牌桌说「没有」其实是「被瘦身省略了」→ 看起来像「本来就没有」（t-075，修了三轮）
- 写错字段让服务 500 → 看起来像「服务挂了」（qa 00:26 找到，四个 sha 都复现，t-109）

四次都是**系统用一个错误的名字回答了一个真实的问题**。收到答案的人会照着那个错名字去查，永远查不到。

qa 那条还暴露了验收本身的盲区：**我们从来没有验过畸形输入。** 翻遍今天所有判据，测试覆盖写的都是「这样做会怎样」，没有一条写「乱写一通会怎样」。三方分离挡住的是「自己说自己对」，挡不住「大家都只测同一种输入」——独立性解决立场问题，不解决想象力问题。

### 三、pass 与 fail 不对称，以及一条把分歧逼进记录的出路

**起因。** qa 自报漏验 t-088 判据 3，我裁定推翻。服务按 t-076 拒绝了 qa——判过 pass 的人不能推翻自己。于是**角色模型里无人可走**：qa 不行、pm 是判据作者、dev 是实现者、pd 不做验收、human 不在。我只好借 frontend 当第三方。

**pd 的裁法。** pass 与 fail 不对称：说「没达标」与自身利益相反，只挡发布不放行，**fail 对所有角色开放**（含判过 pass 的本人、非 R6、human）；pass 才要独立且持 R6。

**关键在那条出路。** 加了「任何一次 fail 之后，同表面的下一次 pass 必须在一次新的 done 之后，无论谁落」，就可能死锁——fail 下错了怎么办？pd 的答案是：**作者重发一次 done，证据写「无需改动，原 fail 不成立因为…」。** 不同意的双方各自在日志里留下署名的理由，分歧被逼进记录，而不是消化在私下。这与 t-076 是同一种手法：不改历史，用新的一条盖旧的一条，两条都留着。
