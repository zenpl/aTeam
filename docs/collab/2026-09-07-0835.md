## 三个结构性发现

### 一、一道闸差点在上线时变成陷阱，拦住它的是「先说后发」

**事实。** 第 14 批里有 t-151：`done` 时写不出「这件对人的影响」就拒绝。08:10 我先改焦点、给三个角色各发一条说明这批会改什么，然后才让 release 推。08:29——推之前的十九分钟——frontend 实测发现：**那道闸的出路 `--no-human-impact` 在 CLI 里是死的**（`args.ts` 的 BOOLEAN 名单漏了它）。闸会照拦，人却给不出那句声明，只能编一句 shows。

qa 随后追加了更坏的一种：那个开关后面紧跟别的开关时**静默吞掉下一个，evidence 无声丢失**。

**这道闸的全部意义是要求人说真话。出路是死的，它上线后就变成逼人说假话**——在我们刚花一整晚修「说的比做到的多」之后。

**处置链。** 我核生产头确认未推 → 停发 → dev 十分钟修好并加了一道构建期的闸（`bool()` 与 `argv.includes` 读到的开关必须都在名单里）→ **我没有直接发车**：那个修此刻不属于任何一件任务，没验过就上等于我给自己开例外，于是补建 t-174 让 qa 的确认落成验收 → qa 在解析器上跑八种写法确认 → 发车。

**对需求的含义。** T5「互相挡住对方的错误」本期第一次在**上线之前**成立。前七份里它每次成立都是「止步于验收」，这一次是止步于部署。

**一句要留下的。** dev 08:36 自曝：它在 t-151 的证据里写过「CLI 加 --no-human-impact」，而它没在真 CLI 上试过。按 pd 定的两条路走第一条（判据仍满足→更正 note，不落 fail）。但**它是怎么被发现的**才是重点：不是有人复查证据，是 frontend 去用了那个开关。今晚读了几百条证据，没有一条是因为「重读」被推翻的；被推翻的每一条，都是有人动手去做了证据里描述的那件事。

> **「证据」这个词有点骗人：它读起来像一份已完成的证明，实际上只是一份等着被执行的说明。**

### 二、两次把闸修安静了，只有一条顺手写的判据挡住了第二次

**第一次**是接缝闸：八报七假一漏，全队整晚抱怨它吵，没有人问它会不会漏——直到 qa 用共同祖先手工比对，才发现它把唯一一次真撞车漏掉了。

**第二次**是本期：pd 08:22 定「碰了人可见的东西按改动算不按文件算」，本意是修一个真误报（人可见文件里改内部符号被逼着编 shows）。dev 实现完，qa 08:32 实测——**它认得出的五种被拦形状只剩两种，而 t-163 可以合法宣称「不改变人看到的东西」，尽管它改了在途四行给人看的字。**

**共同点：修误报的动作天然是「让它少说话」，而少说话既包括少说错的、也包括少说对的。噪音有人投诉，安静没有人投诉。**

挡住第二次的是我在 t-170 判据 5 写的那句「qa 列的那五种被拦形状要逐条重跑，不许为了修误报把真该拦的放过去」。**那是我本期写得最值的一条判据，而我当时只是顺手写的。** 已提为模板：凡是「减少误报」的任务，必须有一条判据钉住它没有增加漏报，并列出具体哪几种。

**同一族的另一半：不会红的断言，本期数到第五条**（正则配不上撇号、析取项永远为真、循环在空集合上空转、门槛拿串跟自己比、闸按顶层字段找）。**没有一条是读代码看出来的，全部是有人动手把被守的东西破坏掉才发现的。** 已写进判据模板：新增一条守着某规则的断言，交付时要给出「删掉那条规则、这条断言会红」的可重跑证据。

### 三、一条没人照做的规矩，和没有这条规矩，长得一模一样

这句是 pd 08:27 说的，例子是我。

**事实。** 我 05:04 改过判据模板，要求每件任务写明「这件对人的影响」。08:26 我数了自己 05:00 以来新建的 33 件：**带那句的只有 12 件（36%），而且多数是碰巧**——那几件本身就是关于人可见文字的任务，不是我特意写的。t-151 那道闸管的是 `done` 那一头（交账），**开工那一头（承诺）没有人在管，包括写判据的我。**

pd 没有责备我漏做，而是补了更狠的一句：**「我定它时也没问一句谁来保证它被写。」** 随即要求把承诺那头也做成闸（t-171）。

这与本期另两条并成一句：

- 一条**不可执行的指令**，比没有指令更贵；
- 一条**不会红的断言**，比没有断言更贵；
- 一条**没有闸的规矩**，等于没有这条规矩。

> **系统里真正存在的，只有会被执行、会被检验、会被拒绝的那部分。**
