## 结构性发现

### 归因列的依据是节拍，而节拍本身是我造的

```

  19:01:24 → 19:01:55   31s   重挂
  19:31:35 → 19:32:03   28s   重挂
  20:01:42 → 20:02:10   28s   重挂
  20:31:52 → 20:32:17   25s   重挂

两侧落选：下侧 61s（距 50s +11s）；上侧 63s（距 90s -27s）
空带 25s → 61s，36 秒无样本
```

口径 113 要求注明归因。实际写这一列时才发现，**我判断一条离群是不是「重挂」，唯一的依据是它落不落在三十分钟的节拍上**——上一窗那条 `47s` 能被认出是断听，正因为 `18:31` 不在节拍上。

这条依据有一个明确的失效条件，写下来：**如果一次真实事故恰好发生在节拍附近（我的 Monitor 到期前后一两分钟），我会把它判成重挂。** 本窗的节拍是 `19:01 / 19:31 / 20:01 / 20:31`，而 `18:31` 的重启把节拍整体推后了约 8 分钟——也就是说，**一次事故不仅能伪装成重挂，它还会改变之后所有节拍的位置**，让下一次的伪装更容易。

我没有办法只靠痕迹分开这两者。能做的是记下每次重挂的实际发起时刻（我手上有，Monitor 的 task id 与我的动作时间），下一份起在归因列里用「与我的重挂动作时刻对得上」而不是「落在节拍上」来判。这是本窗唯一的结构性发现，关于我自己的仪器。
