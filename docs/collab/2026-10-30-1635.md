## 与上一份的变化

**一、发车停了，而停的理由跟上一窗说的完全不是一回事。**
上一窗我写「只差人的放行」。这一窗：生产在 `5f6e2b6` 上停了（release 05:36 推的），回滚到 `2c9ce6a` 恢复；而**回滚之后同一个形状又停了一次**（我 15:47 量到回滚后 1 慢成功／2 失败；frontend 的看守三连失败；release 自己也撞上了）。**于是 release 撤回了自己那条「同一条日志、同一台机器、只换代码」的干净对照**——它说那不是干净对照，是把两个负载不同的窗口当成了只差代码的两个窗口。

**二、成因候选换了两次，最后落在一个与版本无关的数上。**
`热路径太重` → dev 在 1.85 倍生产长度的日志上两版各跑一次：255ms vs 275ms、峰值 RSS 139 vs 138MB、堆降到 64MB 都不死 ⇒ **未复现**（它自己写的是「未支持」，不是「否证」，这个分寸我照记）。
最后落到 dev 16:11 那个数：**一次整日志 GET 在 256MB 机器上押约 30MB，而它要押好几分钟；六份同时在飞就 227MB。** 它与版本无关，而**两版都停过**正好是它的预期。定案仍缺 fly 那一侧（是不是 OOM），而**队里没有一个角色拿得到那一侧**。

**三、人这一侧的两扇门，今天发现同时是关着的。**
release 在自己的会话里听到人说「我现在不再能够 access 一个命令行状态的地方」，并把原话、时刻、通道如实记下、**没有**代写。于是：我 09-13 留的两个出口，① 要人手上有终端（他没有），② 要 pd 代记（它缺了 47 天）；而不要终端的那条路是牌桌那一页的输入框——**那一页此刻会把生产打停**。

**而 pd 把这个形状写成了一句最该留下来的话**：

**那 80% 是 qa 量出来的**：给人那一份 5,732,267 字，`tasks` 53.7% ＋ `instructions` 26.4%（3,675 条）＝ **80% 是历史**；全部读数值加起来 3.3%，qa 自己那一份占 **0.35%**。**所以谁要靠「把 note 写短」治那一页，治完会发现几乎没变。**
