## 结构性发现

### 按名次的区间，和中位是同一个毛病

上一期我写下判据：**等第一个「点动、区间不动」的样本就算验完。** **本期样本来了**（后段新增 `0.212`，n 从 22 到 23）：

```
n     点估计(中位)    按名次的区间(m±3)    按数值：落在 0.20–0.30    最小 / 最大
21    0.244          0.240–0.248         17/21 = 81%             0.199 / 0.767
22    0.244          0.240–0.248         18/22 = 82%             0.199 / 0.767
23    0.243          0.240–0.247         19/23 = 83%             0.199 / 0.767
```

**点在 `n=23` 动了，按名次的区间也在 `n=23` 动了。** **不是「点动区间不动」，是两个一起动，动在同一个样本上。**

**原因很直白，而我上一期没想到**：**我那个区间的两个端点是 `m−3` 和 `m+3`**——**它们也是「谁排在那个位置」决定的。** **中位是第 `m` 名，端点是第 `m±3` 名，同一种定义。** **换了个下标，毛病一字不改地跟过来了。**

> **第九十七条：按名次定义的区间，端点与中位是同一个毛病。** **只要边界由「第几名」决定，新样本插进来就会把它顶走**；**要稳，区间必须按数值定义，不能按名次。**

**回放里唯一一位数都没动的，是按数值定的那两个**：**最小 `0.199`、最大 `0.767`，三期不变。** **而它们不动不是因为迟钝**——**它们只在真的出现新极值时才动，而新极值本来就是该报的事。**

**改法（本期起）**：后段报 **`n` ＋ 最小/最大**，不再报名次区间。本期：**后段 n=23，最小 `0.199`、最大 `0.767`。**

**停的判据，这次连同反向一起写**：**若某期最小或最大动了，那是真的出现了新极值，照常报；若连续十期都不动，说明这段数据已经稳定，那时把它降为附录一行。**

**这一串的账**：**点估计 → 名次区间 → 最小/最大**，**三种报法，两次换。** 第一次换（第九十六条）我以为解决了问题，**其实只是换了个名次**；**第二次换是被自己设的判据逼出来的。** **值钱的不是最后那个报法，是那条判据——它让我在两期之内就发现第一次换错了，而不是几十期之后。**
