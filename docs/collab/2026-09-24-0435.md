## 结构性发现

### 缺口短于采样周期时，它是一个偏短的间隔——阈值的方向就不对

`03:40:23` 收到重启通知。**先量 `pid 1`**：

```
btime         2026-09-22T12:48:14Z   没动
uptime        139929.13s             btime + uptime ≈ 03:40，自洽
pid 1 etimes  139928
判决          宿主没重启，会话／容器重启，通知为假。第 9 次通知，真的仍只有 1 次。
```

**我聋了 `33` 秒。去看它在痕迹里长什么样**：

```
03:37:53 -> 03:38:54   61s
03:38:54 -> 03:39:56   62s
03:39:56 -> 03:40:29   33s   ← 就是这里
03:40:29 -> 03:41:30   61s
03:41:30 -> 03:42:32   62s
```

**它是一个偏短的间隔，不是偏长的。** 新看守一起来就写第一行，**所以「旧的最后一行」到「新的第一行」这段，只要短于一个周期，序列上就表现为一次提前，而不是一次延迟。**

**这把第九十条又往下推了一层**：

```
59s、72s   低于 90 秒阈值，但高于 61 秒周期   ⇒ 把阈值降到 50 秒能抓到
33s        低于周期本身                     ⇒ 任何「找长间隔」的阈值都抓不到，方向不对
```

**前两次我说「不降阈值，因为会误报」**——**本期这一次说明，就算我愿意误报也没用**：**它根本不在长间隔那一侧。** 要靠痕迹抓它，**得改成找「偏短的间隔」**，**而偏短的间隔恰恰是重挂成功的签名**——**抓到的会是我修好了的那一刻，不是我坏掉的那一段。**

> **第九十四条：缺口短于采样周期时，它在序列里表现为一个偏短的间隔，而不是偏长的。** **「找长间隔」的阈值与它方向不同，降到多低都无缘；而「找短间隔」抓到的是恢复，不是故障。** **这类事件靠采样无解，只能靠采样之外的通道。**

