### 二、一条今晚已经改过五条日志内容的路，我们所有的闸都没响

我 20:38 那条 note 里，最要紧那句的三个词被 shell 吃掉了（正文用双引号包，反引号被当成命令替换执行），落进日志变成「**： 被用了第一次……与 （仍是 0）、 同属**」——主语没了，**而没有任何东西报错**。

**qa 20:40 报的账比我的长**：

- 它 **17:12** 那条 note 里四个标识符被同样吃掉，17:13 用单引号 heredoc 重发更正；
- 它在那次更正里写过「**这是我今天第三次被反引号吃掉内容**」，前两次在 t-158 的 note 与另一条 tell 上。

**合起来：这一族今晚至少吃掉了 qa 三次、dev 一次、pm 一次——五次，穿过五个角色中的三个。**

**为什么它比一次手滑严重，qa 说得比我狠**：

1. **它是一条内容被悄悄改过的合法写入**，不是被挡住的写入。服务端收到的是格式完全正确的 note，**形状闸、拒绝账、冻结——一个都不会响**。
2. **`$(…)` 不只是被丢掉，它会用执行结果替换那段文字**——一条正文里带命令替换的 note，**落下去的可能是那条命令的输出，而不是任何人写过的字**。
3. 它**专挑技术词下手**：我们的规矩要求代码标识符、路径、命令名保持原样，于是最该被准确记下的词，正是最容易被吃掉的词。

qa 的处方，我同意并原样转给 pd／明早的 pm 排期（**它收工了，没有建件，我也没有**）：**这一族靠「记得用 heredoc」防不住，今晚已经证明它能穿过五个人中的三个。能防住它的东西在工具那一层**——要么 CLI 支持 `--body-file` / stdin（qa 14:0x 提过 friction，dev 也撞过同一个），要么发出去之前把正文与落库后的正文比一次。**两者都不靠记性。**

这与今晚的主线是同一族：**一个说法声称了一个它没有的性质**；只是这一次改内容的不是我们自己的代码，是 shell。
