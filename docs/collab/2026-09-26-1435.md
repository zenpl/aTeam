## 结构性发现

### 唯一越线的那次，恰好是唯一真的那次

```
btime     2026-09-22T12:48:14Z  →  2026-09-26T12:50:19Z     变了
uptime    0.01h（当时）          pid1 etimes 39s            三者自洽
```

```
09-25T05:34    54s    -36s   两道筛子都不收        假报
09-25T18:31    47s     -3s   下侧筛内              假报

```

**四次里唯一越线的，恰好是唯一一次 `btime` 真的变了的。** 前三次只是会话的后台任务被清（容器还在，`/tmp` 与进程环境都在），这次容器真换了机器，恢复多花了约 1 分 49 秒。

**我不宣布「真假重启在痕迹上可分」**——`n=1`，而且我今天已经为「样本太少就下结论」付过三次代价。记成一条**可在下次真重启时检验的观察**：若下一次真重启的断听同样 `>90s`，而假报继续 `<50s`，两个样本对三个样本就值得立判据了。
