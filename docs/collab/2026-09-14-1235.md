## 三、结构性发现

### 发现一：那张回滚卡不是性能修法，这一条靠第五格才说得准

同机、同库（10,086 条）、同量法，三版代码（`dev` `11:07`／`11:12`，量法是 `qa` `01:23` 写死的那一套）：

| 代码 | 一条写入 |
|---|---|
| `3e50e5b`（**生产此刻真在跑的**） | 764 / 805 ms |
| `09256fd`（回滚前那一版） | 822 / 834 ms |
| `6080756`（HEAD，含那批修） | 318 / 319 ms |

**这三个之间可以相减**（机器同、库同、量法同，只差代码），三条结论：
1. **回滚在写入代价上什么都没动**（两档差在噪声里）⇒「生产变慢是因为被回滚了」**排除**。
2. **那批修值 2.4 倍**，而生产跑的正是没修的那一版。
3. **人那一页那张卡不是性能修法。** 它要推回的 `09256fd` 是 `822–834ms`，**比生产此刻还慢一点**；它买回来的是 `t-223` 那套机制与 `premise` 这一整种事件，**不是速度**。速度在 HEAD。**这一条我特意写下来，免得以后有人（包括我）拿性能去劝那张卡。**

**而下面这个减法仍然不许做**：`production:write.cost.seconds = 2.23–2.77（p50 2.40）` 对 `repo:write.blocks.seconds.prod.build = 0.78`——**差了机器**。我能说的只有一句没有减法的话：**代码与库长这两项已经钉死，合起来是 0.78 秒量级；生产自报 2.40 秒量级。** 我们观察到的机器间差异只有 **20% 量级**（`dev` 674ms 对 `qa` 832–890ms，同长同码），**离三倍差得远**；而 fly 那台**从没人量过**。要合上只有一条路：在 fly 上跑同一套量法，**那要往生产部署量具，正是那张卡还没答的那件事的另一面。我不绕过它。**

### 发现二：做法一变，我写的判据变成了按定义为真

`t-269` `dev` 用了 `-s ours`。它**按定义**就让树一个字节不动，**于是我判据 2、3、4（四个文件在、无删除、`premise` 在）这次是按定义成立，核它们证明不了这次合并对不对。**

真正该核的是它们背后那个前提：**`git rev-list --count 6080756..3e50e5b` 是不是恰好 1、且那一笔就是那条 revert。** 我 `11:18` 量到 1，`dev` `11:20` 独立量到 1 并给了更紧的一条（那一笔的树 `6e01c847` = `d57acbc` 的树，而 `d57acbc` 在合并前分支头里）。已补成判据 8 并单独告诉 `qa`。

> **口径**：**判据是照某个做法写的。做法一变，先问哪几条变成了废话，再谈通不通过。** 一条按定义为真的判据，和一条测不到那个洞的用例，是同一种假绿。

### 发现三：别名被护着，被别名的那个没有

`t-270` 判据 2 交出了今天最干净的一幕（未修时，走 core 真规则）：
```
触点 packages/core/src/board.ts#blockedWhy   ⇒ 落库成功，服务端判它 internal
触点 packages/server/src/html.ts#whyLine     ⇒ REJECTED (done): 这件动了人看得到的字
```
而 `html.ts` 里逐字是 `export const whyLine = blockedWhy;`——**同一个函数**，而它算的是人第一屏那句「为什么卡住」。

**成因是量法的形状**：两把旧尺（有没有中文字面量／读不读 `HUMAN_FIELDS`）问的都是**「这个符号自己写了什么」**，而 `blockedWhy` 是靠**别人拿它做了什么**才成为人可见的。**这一类，两把尺按定义都量不到。**

## 八、口径（本期新增两条，其余与第六十八份同）

- **判据是照某个做法写的。做法一变，先问哪几条变成了废话，再谈通不通过。** 一条按定义为真的判据，和一条测不到那个洞的用例，是同一种假绿。
- **两个数要相减，先证它们只差你要量的那一件。** 差表面不能减、差机器不能减、**差代码版本同样不能减**。
