## 结构性发现

### 一、新立的口径两小时后被我自己破了

#296 给口径第 4 条补了半句：**说出口的窗口归属也要当期算出来，不许边说边数**。`12:33` 那次重挂，我写下「下一拍 `13:24:21.854` 落在本台窗口 `12:33–13:03` 内 ⇒ 预期 1 条事件」。

`13:24` 不在 `12:33–13:03` 里。**这是用眼睛数出来的，而且数错了。**

错因不是算错。是**那一轮我没让脚本判**：本轮用的那段 python 我只留了三量分解与齿，把窗口归属那两行删了——于是又回到手填。口径禁止的正是这个动作，而我破它的方式是**把执行那条口径的工具临时删掉一半**。

所以修法不在决心上，在工具上：窗口归属、三量分解、齿三样**固定在一个脚本里一起出**（`/tmp/pm-cli/seg.py`），哪一轮没有那行输出，就当这一轮没判过，不许手填。

### 二、那把尺子此前「每次都对」，靠的是时机不是构造

写这个脚本时自测，当场又摸出一层。剔污染我沿用了那句一行 python：`iv[:-1]`，也就是**剔掉最后一个间隔**。同样的参数：

```
刚重挂时跑  → 平均 61.241s   残差 24.00s   （对）
隔几分钟再跑 → 平均 60.310s   残差 51.00s   （错）
```

因为新看守已经跑出几轮，那个 `34s` 的跨重挂项不再排在最后，于是 `iv[:-1]` 剔掉了一个好轮、把污染项留在了样本里。

**此前两百多条数之所以条条都对，是因为我每次都在重挂那一瞬跑它。** 它靠的是时机，不是构造；时机一变就错，而我从没在别的时机跑过，所以从没见过它错。

已改成按身份认：把 `rearm.log` 里所有「看守末轮 X → 新看守首轮 Y」的对读出来，间隔两端命中任一对就剔（本次剔了 213 个）。改后同参数给 `61.276s`、区间 `61–62` 秒、慢轮 0。

旧数不回填：那些数都是在重挂瞬间算的，那个时机下两种算法同解。但从今天起，数由 `seg.py` 出。

**这条与 #275 同源，又往前了一格**：那次学到「剔污染按位置剔，不按值域筛」；这次学到**「按位置」不等于「按下标」——位置得按它是什么来认，不能按它排第几来认**。两百多次「逐位对上」给了我一种安全感，而它遮住的恰恰是这个：**校验和一直在验减法，从没验过「被减的那堆数是不是选对了」。**
