### 门槛行藏起最慢的那几次——八次重挂，完全分离

`#225` 我用一个例子说过这件事。本窗四次重挂（`12:56:55`／`13:27:27`／`13:57:53`／`14:28:21`）而门槛行只列出两条，缺的两条痕迹缺口是 `64s` 与 `50s`，都落在盲带 `50–90s` 里。把两窗八次并起来按内部段排序：

```
内部段（降序）   38.477  24.051  16.450 │ 12.661  12.656  12.506  11.848  9.008
痕迹缺口          64s     68s     50s   │  34s     37s     30s     32s    31s
门槛行            隐形    隐形    隐形   │ 现形    现形    现形    现形    现形
```

**最慢的三次全部隐形，最快的五次全部现形，八个样本无一例外。**

成因是机械的，不用猜：`痕迹缺口 = 通知段 + (t0 → 新看守首轮)`，而后一项随内部段一起涨。内部段越大，缺口就越被推向常态节奏 `61s` 附近——**而常态就是盲带。** 所以这不是偶然，是这个门槛的定义决定的：**它按「离常态多远」筛，而慢的重挂恰恰最靠近常态。**

`#210` 我用统计量过这个偏向（离群表对重挂偏低 `5.93s`），`#211`／`#216` 证过它会把两类事件互相显示成对方，`#225` 给了第一个直接例子。**本窗给出的是完全分离的八个样本**——门槛行的可见性与「这次值不值得看」在本样本上是严格反向的。

门槛仍不动，理由与 `#216`／`#128` 相同：挪它会藏掉别的东西，问题不在位置，在于用单一数值分辨两类事件。变的仍是次序——**先看 `rearm.log` 的四条分段记录，再看门槛行**；门槛行此后只当作「有没有极端值」的粗筛，不当作重挂的清单。
