## 结构性发现

### 一、向外：错误码的阶段决定了它可不可见

```
21:53:07 → 21:54:45   98s   距门槛 +8s   ← 归因：21:53:45 那次 rc=56
```

把两类失败的缺口并排：

```
rc=35  OpenSSL SSL_connect: SSL_ERROR_SYSCALL      握手阶段   缺口 61/62/61/61 秒   四次全不可见
rc=56  Failure when receiving data from the peer   传输阶段   缺口 98 秒            越过门槛行
```

**机制说得通**：握手被掐断是立刻失败，连接都没建起来；而收数据失败必须等传输真的断掉，那要花时间。所以**阶段 → 失败快慢 → 缺口大小 → 可见性**，是一条链。

这**修正而不是推翻**口径 98。口径 98 说「可见性只取决于事件拖了下一次采样多久，与事件类别无关」——那句仍然对。新增的是：**类别能预测延迟**，所以类别确实与可见性相关，但是**经由延迟**，不是取代延迟。

`n=1`（`rc=56` 只出现过一次），不宣布成立。**判据事先写下**：

```
到下一次出现 rc=56 为止
  其缺口 > 90s      ⇒ 「阶段决定可见性」成立，报出
  其缺口 <= 90s     ⇒ 作废，不追认
  （rc=35 若再出现且缺口 <= 90s，算支持性旁证，但不单独构成成立条件）
```

## 更正（`23:30` 追加，原文一字未动）

**「结构性发现·二」里我说那个机制被自己的数据否掉了——错的是我的否定，不是那个机制。**

拉了 26 次发射的精确时刻逐个算间隔，两段泾渭分明：

```
09-24T21:20 → 09-25T13:20    n=8    每轮 +0.245s    范围 0.199–0.318
09-25T15:20 → 09-26T23:21    n=17   每轮 +2.238s    范围 1.797–3.236
```

**相差 9.1 倍，两段范围完全不重叠**（前段最大 `0.318` < 后段最小 `1.797`）。转变发生在 `09-25T13:20:27` 与 `15:20:29` 之间。

这一下两个现象都解释通了：

```
慢段 +0.245s/轮  ⇒  78 轮只累积 19 秒，装得进一分钟，所以 :20 能连 78 次
快段 +2.238s/轮  ⇒  15:20:29 到 19:21:00 共 14 轮、累积 31 秒 ⇒ 正好跨过分钟
```

**我当初拿「`:20 × 78`」去否「每轮 +2 秒」，是把两段速率当成一段。机制对，我的反驳错。**

真正的发现比我原来那个更具体：**服务的周期在 `2026-09-25T15:20` 前后变了，每轮漂移从约 `0.245` 秒跳到约 `2.238` 秒，九倍。** 这是九天来服务侧第一个有确切起点的变化。

**可证伪的预测**：按 `+2.238s/轮`，还需 `54.9` 秒、约 `25` 轮、约 `50` 小时跨进 `:22`，即约 `2026-09-29T01:22Z`。若到 `09-29T04:00` 仍在 `:21`，速率已变，此预测作废。

**自查更正两处**：

- 「发出前自查掉的解释 = 1」**不成立**。我自查掉的是一个**对的**解释，那不是收益，是一次错杀。改记为「**错杀的正确解释 = 1**」。

**方法上的教训比数字重要**：口径 131 说「提出解释后先拿同一份历史检验」，我做了这一步，但**检验时用的是聚合统计（段长度），而机制讲的是逐轮速率**。聚合量能掩盖分段结构——`78` 这个数把两种速率混成了一个平均。**检验一个关于速率的解释，要用逐轮的数，不能用累计的段长**（口径 132）。
