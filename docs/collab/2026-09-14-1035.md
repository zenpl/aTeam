## 三、结构性发现

### 发现一：我挂在人拍板页上的选项 A 不能执行，挂了二十小时

**这是本期最重的一条，也是我今天唯一一次把错误写到了人能看见的那一面。**

卡上逐字写的是「放行 `release` 用 `--anyway` 推回 `09256fd`（留痕）」。**我 `10:30` 逐行读了 dev 分支头 `ed2ce79` 的 `packages/cli/src/release.ts`——也就是 release 真会跑的那一份——两条路各卡在一道不同的闸上，而 `--anyway` 哪一道都不管**：

- **`release --deploy 09256fd --anyway`**：`--anyway` 越过的是 `DEPLOY_RULE`（「多出来的提交里有没验收的东西」，`release.ts:400-409`）。越完之后走 `git.push`，它逐字是 `git push <remote> <sha>:refs/heads/production`，**没有 `--force`，注释自己写着 fast-forward only（`release.ts:314`）**。生产头 `3e50e5b` 的父就是 `09256fd`——**往回推是倒退，git 直接拒。**
- **`release --rollback 09256fd --anyway`**：先过 `rollbackTarget`，它读 `b.live?.deploys`（`release.ts:440`），**而生产这一版没有那个字段**（那个字段正是被退掉的 `t-223` 带来的）⇒ null ⇒ `REFUSED (rollback-target)`。**`rollback()` 里没有任何一处拿 `deps.anyway` 去绕这道闸**——`anyway` 只出现在它后面那条 note 的正文里，**而那行代码根本走不到。**

**能执行的那条我也读出来了，而且我们自己昨天用过**：`rollback()` 的做法是**造一笔新提交——树取自目标那一版、父是当前生产头、照常快进推上去**（`release.ts:451` 的注释：「不强推……历史只进不退」）。**`3e50e5b` 就是这么来的。反过来做一次就是出路，不要 `--anyway`，不要 force。**

**处置**：`10:33` 撤回原卡（`01M2E75XHG2K08VKZKMFT5XQZ0`），**同一个问题、换成能跑的动作重发**（`01M2FQNWQXTW89Y5G0GMCMY0ZZ`）。**问人的那一件一个字没改——「谁可以改生产」仍然是他的格。** 依据全文在我 `10:31` 的 note。

**这是那一族的第二十一次**：**我拿一个相邻的、「本该如此」的记录（「`--anyway` 是越闸用的」）代替了对目标本身的观测（「这一次要越的是哪一道闸」）。** 我这两天在别人身上点了二十次，**这一次在我自己身上，而且是在人那一页上。**

**新口径**：**写进人拍板选项里的每一个动作，发之前必须有人真跑一次，或者逐行读过它会走到哪一步。读不出来就不许写成选项——改写成「请你允许我们去试」。**

### 发现二：生产那一笔永远在主线外，等下去不会好

**我 `10:27` 量的三个数**（我的读数树 `/tmp/ateam-cli`，`origin/claude/backend-development-gzqbjf` 头 `ed2ce79`）：

```
git rev-list --count 3e50e5b..ed2ce79   →  59
git rev-list --count ed2ce79..3e50e5b   →   1
git merge-base 3e50e5b ed2ce79          →  09256fd
```

**所以生产不是「退回到某个旧 sha」，是「`09256fd` 加了一笔 revert」**——`3e50e5b` 的提交说明逐字是「回滚到 d57acbc（第 20 批）：内容与那一版逐字相同，历史只进不退」。**那句「历史只进不退」做对了**（它没有强推、没有移动历史）；**而正因为它是新的一笔，它永远在 dev 那条线之外。**

**一个很容易犯的推论在这里是假的**：「等 dev 多推几笔，快进自己就成立了」。**永远不会。** 那一笔不在分支历史里，**`3e50e5b` 不会因为别人往前走而变成谁的祖先；59 这个数只会变大。**

**出路我试了一次，并且撞上了本期第二险的东西**：在一次性 worktree 里把 `3e50e5b` 合进分支头，**git 报六处冲突，而这四个文件在它所谓「自动合并成功」的那一半里被直接删掉，一个冲突标记都没有**：

```
packages/cli/test/rollback.test.ts
packages/cli/test/containment-kinds.test.ts
packages/cli/test/orphan-base.test.ts
packages/core/test/card-stale.test.ts
```

**被删掉的正是守着那套回滚机制的测试。** 同形地，`"premise"` 这个事件种类在合并中间态里也掉了（生产那一版带引号 0 次、分支头 1 次，我两边各 grep 过）。**它被吃掉的表现形式是「一切正常，只是没人能发这种事件了」。**

**已立 `t-269`**，判据把这四个文件和 `premise` 逐个写死，并要求 `git diff --diff-filter=D` 为空。**本件不推生产、不碰生产**——它只拆掉「快进不成立」这一道，推不推、谁来推，仍然等人那一页上那张卡。

### 发现三：三方分离第一次真的挡下了一件——用例绿着，而它测不到那个洞

`qa` 判 `t-256` **fail**，只卡判据 3。**它没有说「这条用例写得不好」，它去破坏被测的东西，然后看用例会不会发现**：把 `distStamp` 改成按 cwd 找，**用例 5/5 全绿，而 binary 报了另一棵树的 sha。**

**所以那条用例是空的：它绿着，与实现对不对无关。** 而判据 3 逐字要的就是「测试必须先红」——**`dev` 那边确实先红过，但红在一条走不到 `distStamp` 的路上。**

**口径收紧一句**：**「先红后绿」只证明用例对某个改动敏感，不证明它对**那个洞**敏感。要证后者，得反过来做一次——把实现改坏，看它会不会红。**

**这条尺 `dev` 一直在对自己的实现用**（它的反向注入 CF1／CF2）；**`qa` 这一次把它用在了 `dev` 的用例上。同一把尺，换了个方向指。** `dev` `10:02` 按窄修法重交，两次注入逐一复现，实现一行没动。

### 发现四：一条测试因为时间流逝自己变红

`alert-line.test.ts` 的 `t-126` 从 `2026-09-14T02:00:03Z` 起在四个 sha 上都红，**包括谁都没改过的 `09256fd`**。成因：**夹具把时刻钉死在 09-07，被测代码用真实时钟，`REACH_STALE_MS` 的七天今天到期。**

**它红着的时候，任何人都 claim 不了「cli 全绿」——这是它排在新活前面的理由。**

### 发现五：qa 回来了、办了四件活、一条 ack 都没发

**`qa` 手上此刻有 8 条逾期未 ack 的指令，而它这两小时判完了其中四件指的活。** 牌桌只看得见前一半。

## 八、口径（本期新增两条，其余与第六十七份同）

- **写进人拍板选项里的每一个动作，发之前必须有人真跑一次、或者逐行读过它会走到哪一步。读不出来就不许写成选项——改写成「请你允许我们去试」。**
- **「先红后绿」只证明用例对某个改动敏感，不证明它对那个洞敏感。要证后者，把实现改坏，看它会不会红。**

**顺带记一条 friction**（已落日志）：发一张 30 天期限的卡，命令行回显印的是「`[ack by 10:33]`」，**只有时分没有日期**。真值是 `2026-10-14T10:33:43Z`，我拉日志核过。**我当场以为自己把 `--ack-by 30d` 打丢了。**
