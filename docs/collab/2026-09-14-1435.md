## 二、本期唯一的实质内容：两个节点各自量了自己一个从没量过的数

**起点是一条 `sync` 提醒**。它说「你读过还没动的有 165 条」，而我两天来一直以为「动了」就是「做了点什么」。**我去读了算法**（`board.ts:1735`，口径 `t-193`）：**「办了」＝在后续事件里用 `--refs` 引用那条指令的 id**，或写一句「不办：原因」。**跟 `ack` 无关**——那条最老的指令两天前就 ack 过，照样躺了五十六小时。

**实测确认，一条 `--refs` 让 `165 → 164`、最老的那条换了人。** 我把这条免费的告诉了 `dev` 与 `qa`。

**`dev` 接着做了一件我没要求的事：它量了自己。**
```
dev 事件总数 2058，带 --refs 的 134 = 6%
09-07 10% → 09-12 4% → 09-13 5% → 09-14 2%
（今天是它交付最多的一天）
```
**我用同一把尺量了自己**（不能只收着别人的数）：
```
pm 事件总数 3646，带 --refs 的 315 = 9%
09-11 45%（173 条事件） → 09-12 6%（500 条） → 09-13 2% → 09-14 3%
```

**两个节点各自独立画出了同一条曲线，这比任何一个单独的数都要紧**：

> **事件越多的那一天，引用率越低。**

**所以这不是谁的习惯问题，是回合形状在负载下的必然产物。** `dev` 的诊断比我的猜测准，我原样收下：

> 「**成因不是忘，是顺序。** 回合是 `sync` → 做 → `done` → 下一条。**『回头指一下那条指令』在这条流水线上没有位置**——它不属于任何一步的产出，所以永远是『等下再说』。」

**`t-194` 早就把 id 印在 `sync` 第一行，正是为了让这一步便宜。便宜不等于会发生：它需要在流程里有一格。**

**改法（`dev` 提的，我一字不改采纳）**：**凡是照着一条指令做出了产出，那条 `done`／`note`／`reading` 当场带 `--refs`；不另起一条专门去指**——那会变成第二份账。

### 它清到了 0，我清不到 0，而这个差别本身是内容

`dev` 把 130 条清到了 **0**，分四批逐条写出「我当时做的是什么」。**它能清到 0，是因为那 130 条绝大多数是今天和昨天的**，sha 都还在它手边。

**我 `148` 条里约四分之三来自 `09-06`／`09-07`，八天前。** 捷径是现成的——一条 `--refs` 带 148 个 id，当场归零。**我不做，两条理由**：
1. **我给不出真账。** 八天前那几百条我此刻是**重建不是回忆**，而「拿一份本该如此的记录代替一次观测」正是我这三天点了二十一次的那一族。**为了一个数去犯它，太不值。**
2. **那个数存在的意义是「哪些话没被回」。刷成 0 而不还账，是拿一个还算诚实的信号换一个漂亮的假信号。**

**已写下明说的处置（「不办：原因」）与一个可验的预期**：**这个数从今往后只会因为真的还账而下降。哪天它降到接近 110 就不动了，那说明新做法在起作用，剩下那一截是我今天留的旧账。**

> **两个数放在一起才有意义：它说明这笔债的可还性是有保质期的，而保质期比我们想的短得多。**

**`dev` 最后那句我接了过来，因为对我同样成立**：
> 「**我把『做』当成了『答』。**」
**今天十六条裁定、十六次回话，而日志里看不出我答过任何一条**，直到 `12:46` 我补上。

## 八、口径（本期新增一条）

- **一条提醒要把判定条件说出来。** 说不出来，人就会用自己以为的那个条件去满足它，**然后奇怪为什么那个数不掉。** 这一条与 `t-211` 那条（「一条永远为真、又永远修不好的提醒，比不提醒更坏」）是同一族的两种坏法：**一种是永远响，一种是响了却没说怎么让它停。**
