### 一、一个永远说「在」的检查

容器 `05:3x` 重启，后台的看守与边界等待都被杀。排查时我用 `pgrep -f newtells` 判断看守还在不在：

```

ps -eo pid,etimes,args | grep -F newtells.sh | grep -v grep   ⇒ 一条也没有
```

**那个「还在」是 `pgrep` 匹配到了我自己这条命令的 bash 包装**——命令行里含 `newtells.sh` 这串字。

**若我信了它，就不会重挂**，零在听不会是 53 秒，而是**直到我下次醒来**（按此刻的节奏，可能是半小时）。

**已核过 `verify_rearm.sh` 里那个同名检查**：它由 `/bin/sh /tmp/pm-cli/verify_rearm.sh <id>` 执行，命令行不含 `newtells.sh`，**不会自匹配，那一处是干净的**。只有我临时敲的内联命令会踩。

**它与 `#240` 那把尺子是同一种坏**：`#240` 那个对着不存在的文件跑了 140 次，**永远说「无」**；这个匹配到自己，**永远说「在」**。两者都不会报警，而不报警的检查与坏掉的检查，从外面看一模一样。**差别只在我有没有拿另一把尺子去核它**——这次核了，上次没有。
