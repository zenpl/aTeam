# aTeam · 牌桌设计

> v2，2026-09-06，样稿经 human 确认「不错」。**pd 拥有此文档。** 依据 human 07:2x 的反馈：现在的页面几乎没有视觉结构，重点、详略、视觉焦点、可操作性、信息颗粒度都有问题。样稿（用真实日志渲染，静态快照）：`docs/board-sample.html`，frontend 可直接取其 CSS token 与结构。frontend 照此实现，qa 验人可见交付时对照此文与 `docs/usecases.md` UC-S1。

## 一句话

牌桌是一个人每天坐三分钟的地方。他来做两件事：把等他的事拍掉，看一眼世界现在什么样。页面的每个像素都为这两件事服务，其余折叠。

## 三个层级

| 层 | 看的方式 | 放什么 | 视觉 |
|---|---|---|---|
| 一眼 | 扫 | 需要你的卡片；焦点一句；在途的计数条；线上一行 | 最大字号、唯一的红色、唯一的主色按钮 |
| 读 | 逐行 | 在做和卡住的任务列表；谁在 | 正文字号，点 + 标题 + 负责人 |
| 挖 | 点开才看 | 做完等验、没开始、验过未上线的列表；这一版带来了什么；团队自己的状态 | 折叠，摘要行带计数 |

规则：任何列表默认展开的行数不超过 5；超过就折叠成「还有 N 件」。首屏（不滚动）里只允许「一眼」和「读」两层。

## 重点与视觉焦点

- **页面上只有一种红**：「需要你」的计数和卡片左沿。红的意思是「你不点，事情就停着」。没有需要你的事时，红不出现，「需要你」缩成一行灰字，视线自然落到「现在」。
- **页面上只有一种主色按钮**：每张卡片里的默认动作。次要动作是描边按钮。一屏里主色按钮的数量 = 需要你做的事的数量。
- **琥珀色只给「卡住」和「逾期」**，绿色只给「在生产上验过」。其他一律墨色或灰色。颜色是状态，不是装饰。
- 段标题是墨色、中等字重、带一条细线；不用小号灰色大写字母当标题。
- 「需要你」里的那句话和焦点用衬线字（Noto Serif SC 及其回退）：它们是要被认真读的句子。其余用无衬线。sha 用等宽。

## 可操作性

每张「需要你」的卡片先说清它是哪一种，动作跟着种类走：

| 种类 | 什么时候 | 动作 |
|---|---|---|
| 问你 | 指令带选项 | 一个选项一个按钮；默认项是主色按钮并标「默认」；旁注「不点的话，到期按 X」 |
| 请你做 | 指令要你去做一件事（部署、开一次 token 页） | 主色「做好了」，描边按后果二选一：这次不做写「先不做」，永久关掉这张卡写「不要了」——按钮必须说出后果，两者不能同字（pd 09-07 00:3x，外呼那张卡永久关闭却写着「先不做」是我的错）。两者都是 ack；不追问原因，点完后结果语后面跟一句「想说一句就说」，光标落进已有的说一句框，不新增控件、不设必填 |
| 告诉你 | 只是让你知道 | 主色「知道了」 |

- 按钮永远可点。匿名状态下点按钮跳到一个只让输 token 的小页面再回来（决策 A 的提示改法退役，改为这个）。
- 回答后卡片消失，卡片下方出现一行「你刚定了：… → X」，让人确认自己点对了。
- 「跟团队说一句」输入框固定在「需要你」和「现在」之间：这是人对团队唯一的输入口（UC-S2）。

## 信息颗粒度

- **给人的指令写法**：第一句是动作或问题，不超过 30 字；细节（分支名、sha、任务 id）放在冒号或句号之后。牌桌把第一句作为标题，其余折进「细节」。写不出第一句的指令不该发给人。
- **任务一行**：状态点 + 标题 + 负责人小标签。卡住的任务多一行琥珀色的原因，截到 60 字。不显示 id、判据、证据；这些在「挖」层。
- **线上一行**：短 sha + 「在生产上验过 N 件」+ 谁在多久前核对。「这一版带来了什么」折叠。
- **在途计数条**：每组一个小标签「N 在做」「N 卡住」…，卡住的标签琥珀色。计数条在列表之上，先给数再给项。
- **谁在**：名字 + 绿点 + 多久前；十分钟没动静变灰。不显示 idle 秒数。
- **时间**一律相对：刚刚、N 分钟前、N 小时前、N 天前。绝对时间放在 `title` 里。

## 版式

- 单栏，最宽 52rem，正文 15px/1.7。中文行高必须 ≥ 1.6。
- 「现在」是一张卡；「需要你」的每条各是一张卡；「说一句」不是卡；其余折叠区不是卡。卡的数量就是页面上「独立对象」的数量，不多不少。
- 标签列固定 4.5em，值列自适应；窄屏（< 540px）标签换到上方。
- 暗色主题同一套 token，对比度不低于浅色。

## 挖层的「团队」一行

折叠区第一行是团队自己的健康：「职责 18 项：16 有人；R9 发布没有节点能推；R13 报告无人」（T12 职责覆盖）、「分配：2 条预警」（T13，详情在协作报告）、未决接缝数、逾期数、最近一份协作报告的链接。它是团队的事，所以在挖层；但 owner 起项目时会收到一张「告诉你」卡说清缺什么。

## 空态

| 位置 | 文案 |
|---|---|
| 需要你 | 没有等你的事。 |
| 焦点 | 还没有焦点 |
| 线上 | 还没人核对过线上是哪一版 |
| 在途 | 没有在途的事 |
| 谁在 | 还没有人 |
| 你说过的 | （不显示这一节） |

## 不做

- 图表、头像、动画。
- 首屏出现 id、路径、长 sha、判据、证据。
- 给 agent 看的任何东西出现在折叠之外。

## 验收（qa 对照）

1. 首屏一屏之内只有：需要你的卡（或一行空态）、你刚定了、说一句、现在（焦点、线上一行、在途计数条 + 在做/卡住列表、谁在）。
2. 页面上红色元素只属于「需要你」；主色按钮数量等于需要你做的事的数量。
3. 每张需要你的卡都有种类标签和对应的按钮；匿名点按钮走 token 小页面而不是禁用。
4. 任何默认展开的列表不超过 5 行。
5. 给人的指令第一句不超过 30 字时作为标题显示，其余在「细节」里。
