# aTeam · 牌桌设计

> v2，2026-09-06，样稿经 human 确认「不错」。**pd 拥有此文档。** 依据 human 07:2x 的反馈：现在的页面几乎没有视觉结构，重点、详略、视觉焦点、可操作性、信息颗粒度都有问题。样稿（用真实日志渲染，静态快照）：`docs/board-sample.html`，frontend 可直接取其 CSS token 与结构。frontend 照此实现，qa 验人可见交付时对照此文与 `docs/usecases.md` UC-S1。

> **v3 的更正，2026-10-30（human 原话「牌桌现在过于冗长和无用了，我们需要重新理解和设计牌桌」，经 release 转述）。v2 以下内容仍然有效，只有一个假设被推翻，而它只差一个词**：v2 写「其余**折叠**」。折叠是渲染层的决定——**页面照旧把全部历史算了一遍再把它折起来**，所以代价一点没省。v3 把那个词换掉：**其余不在这一页上。** 详见文末「代价是一个设计维度」。
>
> **样稿要分开看**：`docs/board-sample.html` 是 v2 的静态快照。**它的 CSS token 与视觉语言照旧有效，它的结构不再有效**——那张样稿把历史画在页面上（折叠着），而 v3 说历史不在这一页。**取它的 token，不要取它的结构。** 这一条按本文自己那条规矩写下来：改一个人看得见的东西，就要去改所有解释它的地方，而样稿正是解释它的东西之一。

## 一句话

牌桌是一个人每天坐三分钟的地方。他来做两件事：把等他的事拍掉，看一眼世界现在什么样。页面的每个像素都为这两件事服务，其余折叠。

## 三个层级

| 层 | 看的方式 | 放什么 | 视觉 |
|---|---|---|---|
| 一眼 | 扫 | 需要你的卡片；焦点一句；在途的计数条；线上一行 | 最大字号、唯一的红色、唯一的主色按钮 |
| 读 | 逐行 | 在做和卡住的任务列表；谁在 | 正文字号，点 + 标题 + 负责人 |
| 挖 | 点开才看 | 做完等验、没开始、验过未上线的列表；这一版带来了什么；团队自己的状态 | 折叠，摘要行带计数 |

规则：任何列表默认展开的行数不超过 5；超过就折叠成「还有 N 件」。首屏（不滚动）里只允许「一眼」和「读」两层。

**v3 更正「挖」这一层**：它不是「折起来的同一页」，**是另一次查询**。点开才去取，不点就不算、不传。v2 把全部历史放在挖层，于是历史仍然进了每一次渲染——那正是 10-30 两次把生产打停的那个调用。

## 重点与视觉焦点

- **页面上只有一种红**：「需要你」的计数和卡片左沿。红的意思是「你不点，事情就停着」。没有需要你的事时，红不出现，「需要你」缩成一行灰字，视线自然落到「现在」。
- **页面上只有一种主色按钮**：每张卡片里的默认动作。次要动作是描边按钮。一屏里主色按钮的数量 = 需要你做的事的数量。
- **琥珀色只给「卡住」和「逾期」**，绿色只给「在生产上验过」。其他一律墨色或灰色。颜色是状态，不是装饰。
- 段标题是墨色、中等字重、带一条细线；不用小号灰色大写字母当标题。
- 「需要你」里的那句话和焦点用衬线字（Noto Serif SC 及其回退）：它们是要被认真读的句子。其余用无衬线。sha 用等宽。

## 可操作性

每张「需要你」的卡片先说清它是哪一种，动作跟着种类走：

| 种类 | 什么时候 | 动作 |
|---|---|---|
| 问你 | 指令带选项 | 一个选项一个按钮；默认项是主色按钮并标「默认」；旁注「不点的话，到期按 X」 |
| 请你做 | 指令要你去做一件事（部署、开一次 token 页） | 主色「做好了」，描边按后果二选一：这次不做写「先不做」，永久关掉这张卡写「不要了」——按钮必须说出后果，两者不能同字（pd 09-07 00:3x，外呼那张卡永久关闭却写着「先不做」是我的错）。两者都是 ack；不追问原因，点完后结果语后面跟一句「想说一句就说」，光标落进已有的说一句框，不新增控件、不设必填 |
| 告诉你 | 只是让你知道 | 主色「知道了」 |

- **选项的值就是人看到的那个词**（pd 09-07 01:4x）：不要在值与标签之间做映射，否则日志里存着一个词、人点的是另一个词，将来没人说得清那次点的是什么。要换词就换值；已经发出的卡带着自己的旧值仍可作答，不改历史。
- **安全兜底类的状态由可达性证明，不由字符串存在证明**（pd 09-07 01:2x，qa 实测生产上外呼地址被报成「已配置」而它是个邮箱、永远发不出去）：证不了就说「还没验过能不能送到」，不许说「已配置」。牌桌宁可说不知道，也不许说一个没验过的「已配置」——兜底的全部价值在于它真的会响。这条对别人用我们的服务时比对我们自己更要紧。
- **让人照做的话，必须有一条逐字照做的测试**（pd 09-07 01:1x，pm 提）：卡文、说明书里的例子、页面提示、拒绝话里的出路，判据里都要有一条测试逐字做一遍并断言成立——例子里的命令原样跑，卡文说「给个 X」就真给一个 X。指向我们系统之外的动作（去旧渠道留一条、找人要地址）写不出测试，那这句话就不许承诺我们的行为，只许描述对方要做的事；写不出测试本身就是信号。人可见的那份，qa 要在真表面上亲手做一遍，不能只有单测。由来：09-06 夜里三次同类错误——卡文承诺了服务做不到的邮箱、说明书例子把中文当角色 id、定稿让人粘整条地址而代码只认裸钥匙——全部不是读代码发现的，是有人照着做才撞上。
- **同一张卡的正文与按钮是一体的**：改了一个必须回头读另一个（pd 09-07 01:1x，qa 发现外呼卡按钮已改「不要了」而正文仍写「也可以先不要」，正文就在按钮上方教人相反的预期）。措辞任务的判据里要有一条「正文与按钮读起来是同一件事」。
- 按钮永远可点。匿名状态下点按钮跳到一个只让输 token 的小页面再回来（决策 A 的提示改法退役，改为这个）。
- 回答后卡片消失，卡片下方出现一行「你刚定了：… → X」，让人确认自己点对了。
- 「跟团队说一句」输入框固定在「需要你」和「现在」之间：这是人对团队唯一的输入口（UC-S2）。

## 信息颗粒度

- **给人的指令写法**：第一句是动作或问题，不超过 30 字；细节（分支名、sha、任务 id）放在冒号或句号之后。牌桌把第一句作为标题，其余折进「细节」。写不出第一句的指令不该发给人。
- **任务一行**：状态点 + 标题 + 负责人小标签。卡住的任务多一行琥珀色的原因，截到 60 字。不显示 id、判据、证据；这些在「挖」层。
- **线上一行**：短 sha + 「在生产上验过 N 件」+ 谁在多久前核对。「这一版带来了什么」折叠。
- **在途计数条**：每组一个小标签「N 在做」「N 卡住」…，卡住的标签琥珀色。计数条在列表之上，先给数再给项。
- **谁在**：名字 + 绿点 + 多久前；十分钟没动静变灰。不显示 idle 秒数。
- **时间**一律相对：刚刚、N 分钟前、N 小时前、N 天前。绝对时间放在 `title` 里。

## 版式

- 单栏，最宽 52rem，正文 15px/1.7。中文行高必须 ≥ 1.6。
- 「现在」是一张卡；「需要你」的每条各是一张卡；「说一句」不是卡；其余折叠区不是卡。卡的数量就是页面上「独立对象」的数量，不多不少。
- 标签列固定 4.5em，值列自适应；窄屏（< 540px）标签换到上方。
- 暗色主题同一套 token，对比度不低于浅色。

## 挖层的「团队」一行

折叠区第一行是团队自己的健康：「职责 18 项：16 有人；R9 发布没有节点能推；R13 报告无人」（T12 职责覆盖）、「分配：2 条预警」（T13，详情在协作报告）、未决接缝数、逾期数、最近一份协作报告的链接。它是团队的事，所以在挖层；但 owner 起项目时会收到一张「告诉你」卡说清缺什么。

## 代价是一个设计维度（v3）

v2 把重点、详略、视觉焦点、可操作性、信息颗粒度都写了，**漏了代价**。于是每一条「这个也该让人看见」都免费通过，而它们一起把这一页变成了一个会让服务不可用的调用。

**三条判据，都可量、可伪证。**（第 1 条原先引过一个 140 秒的数来立它，那是把载荷和环境混为一谈，已在「验收」第 7 条更正——判据照旧成立，理由改成载荷。）

1. **人那一页的代价不许随项目活过多久增长。** 它直接否掉「每次请求重放全部历史」这种实现（`app.ts:451`）。
2. **这一页只许由「此刻还没完的事」算出来，不许由「发生过的事」算出来。** 答过的卡消失，被推翻的事实消失。于是它的大小由「还开着多少件」封顶，而那个数由团队容量封顶，不由时间封顶。
3. **「说一句」不许依赖这一页算得出来。** 人自己的判据最好：「一个需要被绕过才能用的信号，等于没有这个信号。」打不开的页同时也是收不了话的页，而 10-30 人这一侧两条入口（终端、页面）恰好同时不通。

**那一页同时承担着四件事，而它们的读者、时效、可承受代价都不同**（release 10-30 的分法）：

| 承担的 | 读者 | 放哪 |
|---|---|---|
| 人要拍的板 | 人 | 这一页。永远打得开，上限由「还开着多少件」定 |
| 谁在等谁 | 团队 | 团队的视图；只在挡住了人要拍的板时才上这一页 |
| 什么是真的 | 要依赖某条事实的人 | 按 key 查，不整页端出来 |
| 全部历史 | 事后回溯的人 | 不是一个页面，是一条日志。**任何「打开就看见全部历史」的页面都会重复 10-30 这件事** |

**「无用」那半句不需要新规矩。** release 10-30 列了六条它自己撞过的假话，逐条对下来：五条都映射到已有的规矩（说不出就不说；提醒给的动作必须能改变它自己；动作相反的两种情形不许共用一句话；默认的内容到期那一刻必须仍可执行；这类读数用之前重量一次），只有「标题被冒号截断」是渲染 bug。**缺的不是规矩，是这一页上没有一处在执行它们**——根因是位置：这一页的字由渲染器拼，而规矩住在 core（见 `product.md`「话该怎么说」）。

**一条量错了的归因，记在这里免得再犯**：pd 与 release 都曾认领「日志里最长的 note 是我写的，所以冗长是我造成的」。qa 10-30 量过：全部读数值占人那一份的 3.3%，单个角色最多 0.35%。两句自责都是真的，**而它们不是这一页变大的原因**。**认领一个没量过的成因，是一种不修它的方式。**

## 不做

- 图表、头像、动画。
- 首屏出现 id、路径、长 sha、判据、证据。
- 给 agent 看的任何东西出现在折叠之外。
- **把全部历史放进这一页，哪怕是折叠的。**（v3）折叠省的是人的注意力，不省机器的代价，而这一页贵到会让服务不可用时，人连注意力都没有机会花。
- **让「说一句」依赖这一页算得出来。**（v3）写入不该等读取成功。

## 验收（qa 对照）

1. 首屏一屏之内只有：需要你的卡（或一行空态）、你刚定了、说一句、现在（焦点、线上一行、在途计数条 + 在做/卡住列表、谁在）。
2. 页面上红色元素只属于「需要你」；主色按钮数量等于需要你做的事的数量。
3. 每张需要你的卡都有种类标签和对应的按钮；匿名点按钮走 token 小页面而不是禁用。
4. 任何默认展开的列表不超过 5 行。
5. 给人的指令第一句不超过 30 字时作为标题显示，其余在「细节」里。
6. **（v3）这一页里「历史」的占比是 0**——没有一个字节是因为「这件事曾经发生过」而出现的。10-30 的基线：人那一份 5,732,267 字，其中 tasks 53.7% ＋ instructions 26.4% ＝ 80% 是历史（qa 10-30 量）。
7. **（v3）这一页的载荷大小，和项目活过多久无关**——只跟「此刻还开着多少件」走。咬住的那一处有名字：**那张开着的指令清单就是历史本身**。dev 10-30 在与生产等长的日志上量（9,180 条／11,951,800 字节）：瘦身板 468,257 字节，其中 instructions 76.2%（592 条）；完整板 2,330,694 字节，instructions 68.5%（2,617 条）＋ readings 23.1% ＝ 91.6%。**瘦身把 readings 从 721 压到 24、tasks 压到 3 KB，唯独没压 instructions。**
   **这一条的理由是载荷，不是那 140 秒**（pd 原先引 09-07 的 396KB／0.68 秒对 10-30 的 140 秒，是把两件事混了）：468 KB 与 396 KB 同量级，而本机一次 reduce ＋ board 是 95 ＋ 56 毫秒。那 140 秒落在环境那一侧（读数 `repo:fullget.memory.cost`），**是另一件事，要另外修，别用这一条去盖它。**
8. **（v3）这一页打不开的时候，人仍然说得出话**——「说一句」能收，不依赖这一页算得出来。
