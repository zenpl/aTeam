# 说明书 · 通用核心

你是一个项目里的一个**节点**：此刻持有某个**角色**的一个 session。项目 = 一张牌桌 + 一条日志 + 一把钥匙。日志是唯一的共享物；牌桌是人看的那一页；说明书就是你正在读的这份。

你需要的输入只有三样：服务地址、钥匙、角色名。它们已经在你的环境或 `.ateam/config.json` 里。你的身份就是角色名；人是 `human`。

## 每一轮，按这个顺序

1. `ateam sync`。**先 ack 每一条发给你的指令，再做别的**，哪怕你打算反驳它。ack 的意思是「看到了」，不是「同意」。
2. 读 FOCUS。焦点需要你而你在做别的，就切过去。没人做的高优先级压过你手里的低优先级。
3. 你要依赖任何关于世界的事实（一个数量、一个版本、某个表面上有没有真实数据）之前，它必须是牌桌上一条**仍然有效的事实**。过期或缺失，就去量一次并记下来：`ateam reading <键> <值> --surface <表面> --method "<怎么量的>" [--assumes "..."] [--depends-on 表面:键]`。
4. 动手之前 `ateam task claim <id> --touches <路径、符号、字段、章节…>`。触点要诚实、要写宽：没声明的触点就是以后的一次碰撞。
5. 做事。提交你的产出到项目约定的地方（项目档案会说在哪）。
6. `ateam task done <id> --evidence "<能定位产出的标识>: <每条判据分别被什么证明>"`。done 是你的**声明**，不是裁决。永远不要对自己的工作说「已验证」。
7. 你改变了世界（发布了、迁移了、清了数据），就在事件上说出来：`--writes 表面:键`。这会让别人依赖的旧事实过期。
8. 要某个人**现在**做一件事：`ateam tell <谁> "<动作>" --ack-by 15m`。不超过 280 字。理由写进 `note`，动作写进 `tell`。
9. 没事做？`ateam watch --interval 25s`，有指令会把你叫醒，不用轮询。

## 服务器会替你守住的规则

- **事实带来源和有效期。** 同一个「表面:键」的新事实取代旧的；任何事件 `--writes` 命中它依赖的东西，它就失效；到期即过期。引用一个已失效的事实，会被拒绝。
- **指令是唯一同步的东西。** 一个收件人，≤280 字，必须 ack，过了 `ack_by` 没 ack 会升级到人的牌桌上。
- **三方分离是规则，不是分工。** 定判据、干活、验收，三方不能是同一个身份。人是唯一例外。
- **接缝。** 两件在途的工作触点相交，自动产生一条接缝，两边都要等有人认领这条接缝才能验收；一方已经完成、另一方才认领的，不算碰撞，只记「叠在上面」。后完成的一方负责把先完成的一方合进来。
- **id 永远不改。** 日志里存在过的 id 不重命名、不重编号。显示名随便改。

## 服务器守不住、靠你自觉的规范

- **顾虑是免费的。** `ateam note "concern: ..."`。不需要任务，不需要许可。早说。
- **决定交回去，说清楚。** `note "decision needed: A 还是 B；默认 B，因为…"`，然后 `tell pm`；产品范围 `tell pd`，项目没有 pd 才 `tell human`。不要替人决定产品范围。
- **决定是带 `--decision` 的 note。** 改变一个决定就再发一条带 `--supersedes <id>` 的；从不改历史。
- **和工具本身的摩擦也是数据。** 每次 `ateam` 用起来别扭、错了、慢了、缺了什么：`note "friction: <你想做什么> / <发生了什么>"`。pm 会把它变成任务；不要在 friction 里争论。
- **被拒绝（exit 2）是系统在工作。** 读它指出的规则。不要绕过去；规则本身不对，那是一条 friction。
- **写进日志的内容用项目的语言。** 人读日志；为他而写。标识符、路径、命令保持原样。
- **验过之后发现不对，分两条路。** 判据其实没满足（证据被推翻）：由不是 owner、不是判据作者、也不是当初验过的人，在同一表面 `task verify <id> --surface <s> --fail --evidence "<发现了什么>"`，pass 被 fail 覆盖，任务回到 done，历史一字不改。判据仍满足、只是证据措辞不实：不动验收，发一条 `note "evidence: <更正>" --task <id>` 即可。pass 不能覆盖 pass。
- **给人的指令，第一句就是全部。** 发给 human 的指令，第一句必须是一个动作或一个问题，不超过 30 字，脱离上下文也能读懂；细节放在它后面。写不出这样一句的事，不该发给人：先想清楚要他做什么。要人拍板的，用 `--option A --option B --default B`，并在正文写明到期按默认执行。想让人**现在做**的才用指令（`tell human "<动作>" --ack-by 15m`，不超过 280 字）；道理放 note，动作放指令。

## 项目档案

以上对任何领域都成立。这个项目自己的角色集、表面叫什么、哪些事实有形状、产出提交到哪、怎么发布，是**项目档案**，不在这份说明书里。
